# Project status

Updated: 2026-09-18

- **Current state:** **Regulens — Regulatory Intelligence** provides **New Screen / Agent / Sources** workflows and is repository-ready for two independent Vercel projects: a Vite frontend rooted at `frontend/` and a FastAPI backend rooted at the repository root. The backend uses the existing `backend.app.main:app`, bounded CORS, a safe `/health` route, Fluid Compute, and a 300-second function ceiling. Regulatory behavior and accepted data remain unchanged.
- **Coverage:** 3,908 raw table records produce 3,983 rule records: 2,776 normalized, 1,176 requiring manual review, and 31 inactive. There are 3,877 active source-specific substance records. The 1,978 cross-references comprise 872 `aligned`, 1,057 `changed`, 40 `acd_only`, 0 `singapore_only`, and 9 `ambiguous` records.
- **Identity behavior:** An exact EU catalogue name now establishes identity without a linkage gate. If no exact supported regulatory identity is found, the result is the bounded `no_issue_identified_within_scoped_rules` after recording searches of Singapore Parts I/II and ACD Annex II/III. Niacinamide and Aqua follow this path. Diethylene glycol resolves to the unchanged conditional Singapore record through the runtime-only literal `" (except "` search identity and remains professional review because that rule is non-executable. Mystery Extract remains `identity_unresolved`.
- **Linkage status:** The historical EU-to-Singapore linkage pipeline and its zero-decision accepted artifact are retained for audit history but are inactive/deferred. Missing linkage decisions no longer create review findings.
- **Agent input model:** `ingredient_name` is the only required per-row screening field. CAS and the concentration object are optional; formulation ID, formulation name, and Product Context are optional formulation-level fields. RM Name, trade name, supplier, function, Notes, Remarks, comments, and other unmatched columns remain unchanged as source metadata and never enter deterministic screening. When both RM/trade name and INCI/common name are available, the interpreted identity uses the mapped INCI/common-name field. Notes are not required.
- **Agent context handling:** Product Context and Preparation Stage remain distinct. Only an exact, source-backed accepted Product Context is proposed automatically; missing or ambiguous context produces a structured backend-option choice. A missing preparation stage produces a visible global proposal requiring confirmation. Numeric values without units and `QS`/`balance` remain unresolved. No omitted model-declared formulation row is reconstructed by a Python layout heuristic; invalid or incomplete source references get one semantic repair request and then fail recoverably.
- **Agent configuration:** The root `.env` is loaded once with OS-variable precedence. `OPENAI_AGENT_MODEL` selects the parser, legacy `OPENAI_MODEL` is its fallback, and `OPENAI_EXPLANATION_MODEL` independently selects review explanations. Defaults are `gpt-5.6-sol` and `gpt-5.6-luna`. The parser has bounded read-only catalogue/regulatory-search and proposal-validation tools; it has no screening tool. Sessions are memory-only, expire after 60 minutes, and expose safe model/token/tool usage metadata.
- **Review explanations:** `/screen-formulation` runs the pure deterministic engine first, then explains at most 50 review rows in one structured batch. A locked 512-entry process-local cache is keyed by model and deterministic facts. PDF bytes and raw fragments are excluded. Output is checked for exact grounded facts, unsupported numbers, prohibited conclusions, schema/length limits, and one item per row. Any failure uses centralized deterministic guidance while preserving the result. Raw reason codes and explanation provenance are collapsed in the evidence drawer.
- **Current blocker:** The Agent session store is process-local memory. Initial Vercel smoke testing must establish whether upload, answer, retry, and prepare requests remain on an instance containing the session; durable shared session storage is the first post-deployment issue if they do not. The separate 2,313-item regulatory review queue also remains pending professional triage.
- **Known limitations:** CSV is the only Agent upload format. There is no XLSX/PDF formulation upload, persistence/history, background processing, chat, fuzzy matching, general synonym layer, concentration conversion, positive-list coverage, or regulatory synchronization. Sessions and explanation cache entries are process-local. Inline explanation generation may add up to 15 seconds before falling back.
- **Next task:** Create the two Vercel projects without committing secrets, run the documented production smoke tests, and test Agent session continuity across separate requests before adding XLSX ingestion.
